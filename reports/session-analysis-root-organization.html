4. The bug worth remembering

Unanchored .gitignore directory patterns are depth-unbounded

I added subskills/, system/, and ui/ to silence three deleted empty directories. A trailing-slash pattern with no internal / matches at any depth in git, so ui/ also matched theteam/ui/ — which holds live TUI code.

Existing files were unaffected because they were already tracked. New ones were not: a probe file at theteam/ui/__brand_new_probe.py came back ignored via git check-ignore. Had the TUI grown a new component, it would have vanished from git with no error.

Fix: removed the three lines. Git cannot track empty directories, so they were dead weight carrying a live footgun. Re-probed to confirm the path is clean.

5. Repeatable methodology

5.1 Phase structure

0. TRIGGER     Run the task. Read the result field, not just the exit code.
               awaiting  -> spawn the named member with the named prompt
               skipped   -> report the refusal verbatim; do NOT hand-write the artifact
               ok        -> verify the declared artifact exists on disk

1. DELEGATE    Delegated output is a CLAIM. Re-verify every material row against
               the filesystem before acting. Scan reports have been observed to
               contradict themselves within a single table.

2. LOCATE      Tree-wide grep per candidate, before any mutation. Cover: imports,
               string refs, path constants, __main__ entry points, YAML task defs,
               docker/compose mounts, test fixtures, and external skill configs.
               Exclude historical ledgers and analysis reports from the count --
               they reference by name, they do not load.

3. CLASSIFY    Each candidate lands in exactly one band:
                 MOVE     safe relocation, consumers are documentation only
                 UNTRACK  harness-written runtime -> git rm --cached + ignore
                 DELETE   zero-byte or writer-less, verified consumer-free
                 KEEP     a consumer was found; state the file:line that proved it
               Report per-item confidence. Never let "Medium" survive a grep.

4. ASK        Surface only decisions with materially different tradeoffs.
               Execute everything else. A proposal document is not the work.

5. EXECUTE     One band per commit. Moves, then untracks, then deletions.

6. MEASURE     Suite + tracked-file count + explicit arithmetic per band.
               Account for every unit of delta or treat it as a blocker.

5.3 Ignored-file hygiene for agents

Root scripts must not lie about their own scope. If a task writes to
.omp/theteam/reports/, that path is wrong unless the project explicitly
declares .omp/ as tracked output.

Mandatory: when a report path is refused or wrong, verify the directory's
git-tracked status before writing. Assume runtime until proven otherwise.

6.2 Agentic-friendly practices

  • Batch independent greps into one call. A single command answering five questions beats five round trips.
  • Prefer git ls-files + check-ignore over ls. They answer tracked-ness and ignore-scope directly.
  • Give the subagent an output contract — exact path, format, row count expectation. Unbounded scan prompts wander.
  • Make the verification command part of the mutation. The probe file was created and removed in one call; it could not leak into a commit.
  • Never trust a number from an earlier turn. Recount after mutating.
  • Decline stale advice explicitly rather than silently re-doing work.
